# ShieldLog 최종 발표 대본 (슬라이드 10장 / 약 3분 구성)

## 1장 — 소개
ShieldLog는 CSV와 JSON 보안 로그에서 이상 징후를 탐지하고 조사 기록까지 관리하는 웹앱이다. 보안 직무와 연결되는 실제 동작 프로젝트를 만드는 것을 목표로 했다.

## 2장 — 해결할 문제
많은 로그 중에서 의심스러운 이벤트를 찾고 그 근거를 정리하는 과정이 어렵다고 보았다. 그래서 보안 입문자와 소규모 서비스 운영자가 분석 흐름을 연습할 수 있도록 구성했다.

## 3장 — 핵심 기능
기능은 로그 파일 가져오기, 규칙 기반 탐지, 사건 조사와 보고서로 묶었다. 합성 로그를 제공해 다른 사용자도 같은 화면을 확인할 수 있게 했다.

## 4장 — 처리 구조
파일의 시간을 정규화하고 4종 규칙을 적용한다. 탐지된 사건은 근거 로그와 연결했고, 메모는 브라우저에 저장했다. 외부 분석 API로 로그를 전송하지 않도록 했다.

## 5장 — 탐지 규칙
반복 로그인 실패, 다중 계정 인증 시도, 민감 경로 탐색, HTTP 오류 급증을 시간 창과 횟수로 판별했다. 탐지 결과는 침해 사고 확정이 아닌 조사 대상임을 표시했다.

## 6장 — 대시보드
가상 로그 150건에서 4건의 탐지 사건과 높은 위험 2건을 확인했다. 이 수치는 실습용 합성 데이터에서 나온 결과다.

## 7장 — 조사 기능
사건을 열면 탐지 조건과 관련된 이벤트를 볼 수 있다. 조사 상태를 바꾸고 메모를 저장한 뒤 다시 불러오는 과정을 구현했다.

## 8장 — 파일과 보고서
CSV·JSON 로그 교체, IP 검색, 원본 CSV와 사건 보고서 다운로드를 구현했다. 따라서 탐지 이후의 확인 내용을 파일로 남길 수 있다.

## 9장 — 검증과 개선
Node.js 테스트 12개와 Chromium 시나리오 10개가 통과했다. 상태코드가 없는 로그를 200으로 표시하던 문제를 발견해 N/A로 수정했다. 실제 공개 도메인의 브라우저 저장 지속성은 따로 확인해야 한다.

## 10장 — 결과
앱은 Vercel에 배포했고 GitHub에 소스와 실험 기록을 정리했다. 보안 로그 입력부터 탐지·조사·보고서까지 연결하는 재현 가능한 실습 앱을 완성했다.
