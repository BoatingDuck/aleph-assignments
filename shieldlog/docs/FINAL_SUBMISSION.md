# ShieldLog | ALEPH 프리미엄 실습 최종 제출 (3/3)

> 2026-11-06 작성. 제출란에 입력할 서술형 문구는 `~했다.` 문체를 사용했다. 자동화 결과를 실제 사용자 피드백으로 표현하지 않았다.

## 1. 이번에 만든 것

보안 이벤트 탐지·분석 앱 ShieldLog를 완성했다. CSV·JSON 로그를 브라우저에서 불러와 분석하고, 반복 로그인 실패·다중 계정 인증 시도·민감 경로 탐색·HTTP 오류 급증의 4가지 이상 징후를 탐지하도록 구현했다.

탐지 사건별 근거 이벤트와 위험도를 확인하고, 조사 상태 및 메모를 저장한 뒤 다시 불러올 수 있도록 했다. 원본 이벤트 검색과 CSV 내보내기, 사건 보고서(Markdown) 다운로드, 모바일 화면도 구현했다. 가상 로그 150건으로 초기 화면을 구성했으며, 탐지 사건 4건과 높은 위험 사건 2건을 확인했다.

최종 검증에서 탐지 엔진 테스트 12개와 Chromium 기능 시나리오 10개가 모두 통과했다. 소스는 GitHub에 기록하고 Vercel 프로덕션에 배포했다.

## 2. 확인하는 방법 (3단계 이내)

1. ShieldLog 공개 주소에 접속해 합성 로그 150건, 탐지 사건 4건, 높은 위험 사건 2건이 표시되는지 확인한다.
2. 탐지 사건을 열어 근거 로그를 확인하고 조사 상태와 메모를 저장한 뒤, 새로고침 후 다시 확인한다.
3. 사건 보고서를 다운로드해 저장한 내용을 확인하고, CSV·JSON 로그 가져오기와 원본 이벤트 검색·CSV 내보내기가 동작하는지 확인한다.

## 3. 바뀐 점과 이유

초기에는 실제 서버에서 로그를 직접 수집하는 방식도 고려했지만, 외부 서버에 민감한 데이터를 전송하지 않고 실습 결과를 재현할 수 있도록 브라우저 기반 CSV·JSON 분석으로 범위를 조정했다. 또한 로그 탐지만 보여주는 화면에서 사건 상태·메모 저장과 보고서 생성까지 이어지는 분석 흐름으로 확장했다.

2차 점검 과정에서는 상태코드가 누락된 로그가 정상 HTTP 200으로 표시되는 문제를 발견했다. 없는 정보를 정상 처리한 것으로 오해하지 않도록 누락값을 `N/A`로 표시하도록 수정했고, 재발 방지용 자동 테스트 2개를 추가했다.

## 4. AI에게 맡긴 일과 내가 판단한 일

AI에게 앱 구조 설계, 규칙 기반 탐지 엔진, 화면과 파일 입출력 기능 구현, 자동 테스트, 배포, 제출 문서 및 발표 자료 작성을 맡겼다.

나는 보안 직무와 연결되는 앱을 만들기 위해 보안 이벤트 탐지·분석을 주제로 선택하고, 중간 점검에서 약속한 기능을 실제로 완성·검증하도록 요청했다. 탐지는 침해 확정이 아니라는 점과 실제 사용자 평가를 자동 테스트로 대체해 주장하지 않는 원칙을 유지하도록 했다.

프로젝트 방향과 제출 여부는 내가 결정했으며, 테스트로 입증되지 않은 부분은 별도의 확인 항목으로 남겼다.

## 5. 다음에 할 일

최종 제출 후 실제 브라우저에서 핵심 기능을 직접 시연하고, 사용자 피드백을 받게 된다면 검색·조사 화면의 사용성을 보완할 계획이다. 실운영 적용을 검토할 때에는 개인정보 비식별화, 접근 통제, 데이터 보관 정책, 탐지 규칙의 오탐·미탐 평가를 추가할 예정이다.
