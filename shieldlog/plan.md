# ShieldLog — 프리미엄 실습 앱 프로젝트 계획서

- **프로젝트:** ShieldLog (보안 이벤트 탐지·분석 웹앱)
- **버전:** v1.0 / 2026-11-06
- **결과물 URL:** https://shieldlog-premium.vercel.app/
- **제작 형태:** 브라우저에서 직접 실행되는 정적 웹앱 (HTML, CSS, JavaScript)

## 1. 한 줄 소개

보안 로그를 브라우저에서 분석해 의심스러운 패턴을 탐지하고, 근거 확인부터 대응 기록까지 한곳에서 관리하는 보안 이벤트 분석 웹앱입니다.

## 2. 누구를 위한 것인가

웹서비스를 운영하는 개발자, 보안 분야 학습자, 보안 로그를 처음 검토하는 주니어 보안 담당자가 대상입니다. 특히 초기 보안 분석 업무를 실습할 수 있도록 실제 서버 권한이나 외부 계정 없이도 합성 샘플 로그를 제공하도록 설계했습니다.

## 3. 핵심 기능 3가지

1. **로그 입력·규칙 기반 탐지:** CSV·JSON 로그를 최대 2MB/4,000행까지 가져오고, 반복 로그인 실패·다중 계정 인증 시도·민감 경로 탐색·HTTP 4xx 급증을 탐지합니다.
2. **사건 조사·상태 기록:** 탐지된 사건별 위험도와 근거 이벤트를 확인하고, `미확인 / 조사 중 / 조치 완료` 상태와 조사 메모를 브라우저에 보관합니다.
3. **시각화·검색·결과 내보내기:** 이벤트 추이·유형 분포를 시각화하고 로그 검색, 원본 CSV 및 Markdown 사건 보고서 다운로드를 지원합니다.

## 4. 완료 기준

- 첫 접속 시 합성 샘플 **150건**으로 탐지 유형 **4종, 사건 4개**가 화면에 나타나야 합니다. 샘플 숫자는 알고리즘 동작 확인용이며 실제 침해 통계가 아닙니다.
- 사건 1건을 열어 근거 이벤트를 확인하고, 상태와 메모를 저장한 뒤 새로고침해도 기록이 유지되어야 합니다(저장소 허용 브라우저 기준).
- 사용자가 만든 CSV/JSON을 가져올 수 있어야 하며, 사건 보고서 및 원본 CSV를 다운로드할 수 있어야 합니다.
- 데스크톱과 모바일에서 주요 기능을 사용할 수 있어야 합니다.
- 개발 검증(단위 테스트 및 브라우저 점검)과 공개 배포를 확인할 수 있어야 합니다.

## 5. 서비스 흐름

1. 대시보드에 접속하여 합성 샘플 이벤트와 탐지 결과를 확인합니다.
2. 로그 가져오기에서 사용자 파일을 선택하거나 샘플을 유지합니다.
3. 탐지된 사건을 열어 시간·출발지·요청 경로·HTTP 상태 등 근거를 확인합니다.
4. 사건 상태와 조사 메모를 저장하고, 결과 보고서를 다운로드합니다.

## 6. 탐지 로직 및 자료 범위

| 규칙 | 탐지 조건 | 위험도 |
|---|---|---|
| 반복 로그인 실패 | 동일 출발지 IP·계정, 10분 내 인증 실패 5회 이상 | 높음 |
| 다중 계정 인증 시도 | 동일 IP, 15분 내 인증 실패 6회 이상 및 서로 다른 계정 3개 이상 | 높음 |
| 민감 경로 탐색 | 동일 IP, 15분 내 서로 다른 민감 경로 요청 4개 이상 | 보통 |
| HTTP 오류 급증 | 동일 IP, 5분 내 HTTP 4xx 응답 12회 이상 | 보통 |

`*.env`, `/.git`, `/admin`, `/wp-admin` 등 일부 경로 패턴을 민감 경로로 봅니다. 이 규칙의 일치는 **침입 확정이 아닌 조사 우선순위 안내**입니다.

**데이터:** 초기 시연 데이터는 문서용 IP 범위(RFC 5737)를 사용한 가상 로그입니다. 실사용 데이터는 네트워크 요청 없이 브라우저 내에서 처리됩니다. 가져온 로그/조사 메모는 해당 브라우저의 로컬 저장소에 보관되며 용량이나 사용자 설정에 따라 영속 저장이 제한될 수 있습니다.

## 7. 구현 기술과 구조

- 프런트엔드: 의존성 없는 HTML / CSS / ES Modules(JavaScript)
- 탐지 엔진: `engine.mjs` (파일 파서, 정규화, 시간 창별 탐지 규칙)
- 화면 및 상태 관리: `app.mjs` (시각화, 검색, 사건 조사, 파일 내보내기)
- 데이터 저장: 브라우저 `localStorage` (서버 DB 및 계정 로그인 없음)
- 호스팅: Vercel 정적 서비스, 프로덕션 주소 `https://shieldlog-premium.vercel.app/`
- 자체 검증: Node.js 테스트 10항목, Chromium 브라우저 동작 테스트

## 8. 진행 단계와 버전 관리

| 단계 | 구현 및 확인할 내용 | 증거 |
|---|---|---|
| 목표 확정 | 사용 대상, 문제, 핵심 기능 3개 및 완료 기준 확정 | 본 문서 1~4절 |
| 계획 v1 | 입력 형식·탐지 임계값·UI 구성·검증 기준 정의 | 본 문서 5~7절 |
| 중간 점검 1차 | 4종 탐지·샘플 데이터·대시보드·단위 테스트 확인 | `docs/CHECKPOINT_1.md` |
| 중간 점검 2차 | 사건 메모 지속·파일 가져오기·보고서 출력·모바일 확인 | `docs/CHECKPOINT_2.md` |

**주의:** 위 단계는 개발상 구현과 검증을 정리한 것이며 ALEPH Workbench의 각 점검 버튼을 실제로 접수하거나 통과 판정을 받은 뜻은 아닙니다. Workbench에서 별도 접수가 필요합니다.

## 9. 원안 대비 바뀐 점과 이유

- 초기에 외부 서버 로그 자동 연동도 검토할 수 있었으나, 실습에서 재현 가능하고 민감 로그의 외부 노출을 줄이기 위해 **브라우저 로컬 CSV/JSON 분석**으로 범위를 정했습니다.
- 실제 공격을 확인했다고 오인하지 않도록 탐지 결과의 용어를 **의심 징후·규칙 기반 탐지**로 명시했습니다.
- 중간 점검에서 반복해서 확인하기 쉽도록 자동 생성 합성 샘플과 3단계 재현 절차를 추가했습니다.
- 외부 데이터베이스 대신 브라우저 저장소를 활용하여 설치·인증 없이 조사 기록 저장을 검증하도록 했습니다.

## 11. 제외 범위와 제한

실제 서버로부터의 실시간 수집, IDS/IPS 자동 차단, 침해 사실의 확정, 복수 분석가 간 동기화, 사용자 로그인, 서버 DB는 이번 범위에 포함하지 않았습니다. 샘플 로그의 날짜·IP·사건은 재현용 합성 데이터입니다. HTTP 로그의 포맷별 필드 이름 차이가 있어 원본 파일 형식을 확인한 후 가져와야 합니다.

## 12. AI와 사람의 역할

- AI: 요구사항 구조화, 보안 탐지 로직·화면·시연 데이터 구현, 자동 테스트 및 브라우저 점검, 배포, 제출 문서 초안 작성.
- 사용자: 보안 이벤트 탐지 앱이라는 프로젝트 방향 선택, 실제 제출 기준 검토 및 최종 제출 여부 결정.
- 미수행 작업을 완료했다고 기재하지 않으며, 실제 서비스 검증과 ALEPH 점검/접수는 제출자가 직접 최종 확인합니다.
