## 짧은 확인 방법 4줄

- **위치:** T08 배포 주소의 공개 소개 아래 ‘비공개 자리’로 이동합니다.
- **행동:** PC에서 ‘휴대폰 패스키로 로그인’을 누르고 QR을 아이폰으로 스캔한 뒤, 아이폰에서 패스키 인증과 PC 로그인을 승인합니다.
- **통과:** PC 화면이 자동으로 로그인 상태로 바뀌고 해당 계정의 가상 비공개 기록 3건이 표시됩니다.
- **거절:** 로그인하지 않은 사용자는 비공개 기록을 열 수 없으며, 다른 계정의 기록 직접 조회는 403으로 거절됩니다.

## AI와 내 판단 3줄

- **AI에게 맡긴 일:** T01 공개 소개를 유지하면서 패스키 인증, 휴대전화 QR 승인, 서버 검증과 자동 테스트를 구현하고 점검했습니다.
- **직접 판단한 일:** PC에서 USB 보안키 선택창에 의존하지 않고 아이폰 패스키로 승인하는 방식을 선택했고, 실제 기기에서 로그인과 비공개 기록 표시를 확인했습니다.
- **따르지 않은 제안:** PC의 기본 USB 보안키 인증창에 의존하는 방식은 사용하지 않고, PC와 아이폰을 QR로 연결하는 방식으로 수정했습니다.

## 확인된 결과

- 아이폰 패스키 승인 후 PC 자동 로그인: 실제 동작 확인
- PC 및 아이폰의 비공개 기록 조회: 실제 동작 확인
- 등록 취소(C25): 패스키 수 유지 (owner 1, reviewer 2)
- 다른 계정 조회(C39): owner→reviewer 403 및 전후 기록 3건 유지 확인. 반대 방향은 실측 필요
- 비정상 로그인(C30): 미등록 ID 및 잘못된 인증 데이터 403 확인. 정상/실제 변조 서명 쌍은 실측 미완료
- 로그아웃(C33): 옛 세션 요청 거절 메시지 확인. 응답 HTTP 헤더는 실측 미완료
- 운영 DB: 성공적으로 소비된 QR 연결 2건, 사용된 인증 질문 12건, 철회된 세션 12건
- GitHub Actions: Node.js 22 빌드 및 테스트 **31/31 PASS**
- C23/C30/C31/C45의 시험용 키 자동 테스트는 통과. 실제 아이폰 요청을 사용한 해당 항목 전체의 HTTP 실측을 대체하지는 않음

## 제출 전 남은 일

1. 과제에서 요구하는 실측 증거를 전부 제출해야 한다면 C23·C30·C31·C33·C39 반대 방향·C45를 추가로 직접 확인합니다.
2. T01~T07의 Vercel 배포가 불필요하게 시도되지 않도록 배포 설정을 정리한 뒤 PR을 `main`에 병합합니다.
3. 최종 배포 주소, 소스 URL, 비밀번호 없이 공개 화면에 진입 가능한지 다시 확인합니다.
