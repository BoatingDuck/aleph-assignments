## 짧은 확인 방법 4줄

**어디로 가나요:** 결과물의 첫 화면에서 공개 소개를 확인한 뒤 화면 하단의 `나만 볼 수 있는 자리`로 이동합니다.

**세 단계 안에 무엇을 하나요:** ① 시크릿 창에서 공개 소개를 열고 ② 비공개 영역의 잠금 상태를 확인한 다음 ③ 로그인하지 않은 채 비공개 자료 API에 직접 요청합니다.

**무엇이 보이면 통과인가요:** 기존 T01 소개가 로그인 없이 모두 보이고, 비공개 항목의 실제 내용은 서버가 패스키 인증 뒤에만 내려주며, 미인증 요청은 `401`로 거절되면 통과입니다.

**안 될 때는 무엇이 보이나요:** 비공개 기록이 공개 HTML에 보이거나, 무인증 요청에 내용이 반환되거나 `200` 응답이 오면 실패입니다.

## AI와 내 판단 3줄

**AI에게 맡긴 일:** T01을 유지하면서 패스키 등록·인증·계정 분리·세션 해지·서버 접근 제어를 구현할 수 있도록 코드와 검증 절차 구성을 맡겼습니다.

**내가 직접 판단한 일:** `[실험 후 직접 고른 패스키 저장 위치, 두 기기를 선택한 이유, 실제 거절 응답으로 확인한 내용을 작성]`

**AI 제안을 따르지 않은 일:** `[실제 작업 중 제안을 거절했다면 내용과 이유를 작성하고, 없었다면 충돌하는 제안이 없었는지 검토했다는 근거를 작성]`

> **주의:** 위 서식은 바로 제출할 실측 결과가 아닙니다. HTTPS 결과물, 공개키/등록 위치, 질문 비교, 서명 실패, 재사용 거절, 계정 양방향 거절, 삭제 실험 등은 `인증구현설명서.md`를 실제 기록으로 완성해야 통과 여부를 판단할 수 있습니다.
