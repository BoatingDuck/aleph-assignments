## 짧은 확인 방법 4줄

**어디로 가나요:** 결과물의 공개 T01 소개를 확인하고 아래 T08 비공개 영역으로 이동합니다.

**세 단계 이내 행동:** ① PC에서 휴대폰 패스키 로그인을 선택하고 ② 아이폰에서 QR을 스캔해 패스키 인증을 승인한 뒤 ③ PC에 로그인과 비공개 기록 3건이 표시되는지 확인합니다.

**무엇이 보이면 통과인가요:** 인증한 계정의 기록 3건만 보이고, 타 계정 직접 조회는 HTTP 403으로 차단되면 통과입니다.

**안 될 때는 무엇이 보이나요:** 미인증 상태에서 비공개 기록이 보이거나, 로그아웃된 세션으로도 기록 API가 200을 반환하면 실패입니다(실측에서는 401 거절됨).

## AI와 내 판단 3줄

**AI에게 맡긴 일:** 기존 T01 공개 화면을 유지하면서 패스키 인증·QR 연결·Supabase 권한 분리와 테스트 코드를 구현하고 문서를 정리하는 데 도움을 받았습니다.

**직접 판단한 일:** Windows의 USB 보안키 인증창 대신 아이폰에 저장된 패스키를 사용하는 QR 로그인 방식을 선택하고, 실제 아이폰 승인과 PC 로그인·기록 표시 및 HTTP 거절 결과를 직접 확인했습니다.

**AI 제안을 따르지 않은 일:** USB 인증만 반복하거나 아이폰 단축어로 서명 실험을 지속하는 방식을 사용하지 않고, 운영 로그인은 QR 방식으로, 서명 변조·재전송 실험은 PC 가상 인증기로 분리했습니다.

## 실제 수행 요약

아이폰 패스키로 PC 로그인에 성공했습니다. 실패 요청은 Chrome WebAuthn 가상 인증기에서 생성한 별도 시험용 키로 실제 운영 API에 보내 정상 서명 200, 변조 403, 재전송 409, 삭제한 키 403을 확인했습니다. 로그아웃 후 이전 세션 401, 양방향 계정 격리 403, 마지막 키 삭제 409도 확인했습니다. 최종 DB의 두 계정 자료는 각각 3건, 남은 키는 각 1개입니다. Node.js 22 자동 검사 31개가 통과했습니다.

C40도 reviewer 로그인 상태에서 URL·POST 본문의 `account=owner` 위조를 시도해 모두 **200 / 실제 reviewer / 3건** 응답을 확인하고 [이미지](evidence/C40_reviewer_owner_spoof.png)를 첨부했습니다.

가상 인증기 시험을 아이폰 기기의 서명 변조 실측이라고 적지 않았고, 개인키·세션 쿠키·서명 원문은 첨부하지 않았습니다.
