### 예정 세션 저장 방식

- 브라우저: 랜덤 세션 ID를 `HttpOnly`, `Secure`(배포), `SameSite=Lax` 쿠키로 보관
- DB: 세션 ID 원문 대신 SHA-256 해시와 `user_id`, `expires_at` 저장
- 로그아웃: DB 세션 삭제 후 쿠키 만료
- 비밀번호 변경: 해당 사용자의 기존 세션 전체 폐기

### 기존 T06 자료에 붙일 소유권 기준

- `plans`: `user_id`를 직접 보유
- `plan_versions`: `plan_id → plans.user_id`로 소유권 확인
- `tasks`: `plan_id → plans.user_id`로 소유권 확인
- `task_completions`: `task_id → tasks.plan_id → plans.user_id`로 확인
- `execution_logs`: `task_id → tasks.plan_id → plans.user_id`로 확인
- `reflections`: `plan_id → plans.user_id`로 확인
- `security_checks`: `user_id`를 직접 보유하도록 확장
- `GET /api/export`: 현재 로그인 사용자 자료만 모아 한 파일로 반환

> 클라이언트가 보내는 `user_id`는 소유자 판단에 사용하지 않는다. 소유자는 서버가 세션에서 얻은 사용자 ID로만 결정한다.
