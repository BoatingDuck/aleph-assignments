T07 5단계 — 비밀번호 변경 + 기존 세션 전체 폐기

[추가/교체]
- app/api/auth/change-password/route.ts  새 파일
- components/ChangePasswordDialog.tsx    새 파일
- components/AuthenticatedApp.tsx        교체

[동작]
1. 로그인한 사용자가 현재 비밀번호 + 새 비밀번호를 제출한다.
2. 서버가 현재 비밀번호를 bcrypt로 검증한다.
3. 새 비밀번호를 bcrypt로 다시 해시하여 users.password_hash를 갱신한다.
4. 해당 사용자의 sessions 행을 전부 삭제한다.
5. 현재 브라우저 HttpOnly 세션 쿠키도 만료한다.
6. 앱은 로그인 화면으로 돌아간다.

[C114 확인]
A. 비밀번호 변경 전
   - /api/auth/me 요청이 200인지 확인
   - DevTools > Application > Cookies > http://localhost:3000 에서
     t07_session의 기존 Value를 개인 메모에만 임시 보관
     (제출/대화/Git에 절대 적지 않음)

B. 비밀번호 변경
   - 현재 비밀번호 입력
   - 새 비밀번호 입력
   - 성공 뒤 자동으로 로그인 화면으로 돌아가는지 확인
   - 이전 비밀번호 로그인 실패 확인
   - 새 비밀번호 로그인 성공 확인

C. "이전 세션값 자체" 무효화 증거
   - 새 비밀번호로 다시 로그인한 뒤 DevTools > Application > Cookies에서
     현재 t07_session 값을 잠깐 다른 곳에 개인 메모
   - t07_session Value를 비밀번호 변경 전에 보관했던 "옛 세션값"으로 바꾼다.
   - 주소창에서 http://localhost:3000/api/auth/me 를 연다.
   - HTTP 401 / {"ok":false,"error":"로그인이 필요합니다."} 가 나와야 통과.
   - 테스트가 끝나면 정상 로그인으로 새 세션을 다시 발급받는다.

[주의]
- 세션값은 스크린샷/제출문에서 반드시 가린다.
- 실제 비밀번호도 스크린샷/제출문/Git에 적지 않는다.
- 비밀번호 입력 필드는 type=password이므로 화면에 원문을 표시하지 않는다.
