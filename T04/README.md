# 가을의 온도 · T04

기상청 날씨누리 도시별 기상실황표에서 대전 관측소(133)의 최신 측정 기온을 조회해 KST 날짜별로 기록합니다. 표에 제공되는 관측 시각과 이 앱에서 조회한 시각을 분리합니다. 공개 원천 URL에 관측 시각을 포함해 해당 시점의 원자료를 다시 확인할 수 있습니다. 관측소에서 측정한 값이며, 지역 전체가 동일한 온도라는 의미는 아닙니다.

## 사용

1. 실제 정보판에서 `지금 조회하고 기록`을 누릅니다.
2. 일별 기록 대조를 펼쳐 원자료·저장값·화면값과 출처 시각을 확인합니다.
3. 플랫폼에 당일 `t04_day` 영수증을 남긴 뒤 `이 날짜 기록 확정`을 누릅니다. 다음 실제 KST 날짜에 반복합니다.

서버 DB에 기록이 보존됩니다. 같은 날의 반복 성공은 같은 고유 ID를 갱신합니다. 확정된 날짜는 더 이상 덮어쓰지 않습니다. 두 날짜 확보 후 추가 날짜를 만들지 않습니다. 합성 초기화는 실제 기록에 영향을 주지 않습니다. `값 4개 복사`는 플랫폼 영수증 생성 자체가 아닙니다. 플랫폼의 봉인 절차는 해당 플랫폼에서 완료해야 합니다.

## 공개 합성 검사

public/t04-assets의 원본 17개 파일은 asset-manifest.json의 SHA-256과 모두 일치했습니다. 현재 계약 package ID는 `aleph-t04-real-information-board-public-contract-v2`, 계약 버전 2.0.0, fixture 버전 1.1.0입니다. 사용자에게 전달된 안내와 달리 공개 registry는 조건을 35개로 세분화합니다.

실패 버튼은 합성 초기화→D1-A→D1-B→선택 실패를 재생합니다. 정상값 105 pt와 1행을 보존하고 stale/error_code를 보여 줍니다. `다시 시도 · D2 복구`는 T04-RECOVER-D2를 재생해 fresh/none, 120 pt, 2행, 변화 +15를 만듭니다. 정상 D1-B를 반복하거나 복구 D2를 반복해도 행이 늘지 않습니다. 실제 원천과 replay는 lib/reading.ts의 동일한 정규화 검증·성공·실패 전이 함수를 사용합니다. replay 상태는 페이지 안의 합성 시험 상태입니다.

## 확인 방법 4줄

어디로 가나요: 공개 결과물의 실제 정보판과 실패 재생실로 이동합니다.
무엇을 하나요: ① 실제 일별 기록 대조를 펼칩니다. ② 실패 재생실에서 실패를 선택합니다. ③ 다시 시도 · D2 복구를 누릅니다.
무엇이 보이면 통과인가요: 실제 두 날짜 값·원천 시각·단위가 원자료/저장/화면에서 일치하고 변화가 재계산되며, 합성 실패 후 105 pt·1행 보존과 복구 후 120 pt·2행·fresh/none이 보입니다.
안 될 때 무엇이 보이나요: 실패별 설명·오래된 값·다시 시도가 표시됩니다. 실제 둘째 날이 없으면 비교 대기가 표시됩니다.

## AI와 본인 판단: 제출 전 실제 검토에 맞춰 확인할 초안

AI에게 맡긴 일: 공개 API 호출, KST 일별 저장, 합성 장애·복구, 반응형 화면과 애니메이션의 구현을 맡겼다.
직접 판단한 일: 가을 분위기를 유지하면서 기존 페이지보다 생동감 있고 현대적인 디자인을 요청했고, 오늘 첫 기록을 확보하는 일정을 우선했다.
AI 제안을 따르지 않은 일: [최종 화면과 동작을 직접 확인한 뒤 실제 선택에 맞춰 기재한다.]

## 보안과 접근

API는 비밀키가 없는 고정 공개 URL만 호출합니다. 개인 위치를 요청하지 않으며 공공 도시 좌표만 사용합니다. 사용자 개인정보, 로그인, 키 입력은 수집하지 않습니다. 서버가 고정된 기상청 공개 HTML을 조회합니다. lib/kma.ts는 표 머리글·대전 지점 133·현재 기온 열·관측 시각을 검증합니다. 원자료는 기상실황 시각 및 대전 행의 원본 HTML 발췌를 함께 보존합니다. 자료 형식이 바뀌면 schema_error로 처리하며 마지막 정상값을 유지합니다. 원천 관측 시각이 2시간보다 오래되거나 미래 시각인 경우 새 정상 기록으로 저장하지 않습니다. 클라이언트에서 전달한 숫자·날짜·원자료는 실제 기록으로 저장하지 않습니다. 초기 Open-Meteo 모델 실험은 별도 테이블에 남아 있지만 실제 정보판과 제출용 기록에는 포함되지 않습니다. 공개 소스 ZIP은 commit SHA를 포함하는 URL로 전체 추적 소스를 제공합니다. 환경변수·빌드 캐시·실제 DB·Git 인증값은 소스 ZIP에 포함하지 않습니다.

## Vercel 배포와 데이터베이스

일반 Next.js 앱으로 빌드하며 Neon Postgres를 영구 저장소로 사용합니다. Vercel Marketplace에서 Neon을 프로젝트에 연결하고 `DATABASE_URL`을 제공해야 합니다. 첫 API 요청에서 `daily_observations`와 `board_observations` 테이블을 만듭니다. 현재 Site의 D1 DB와 새 Vercel DB는 별개이므로 실제 기록 이관은 [VERCEL_DEPLOY.md](./VERCEL_DEPLOY.md)를 따릅니다. `.env.local`과 실제 관측 JSON 파일은 저장소에 올리지 않습니다.

로컬에서는 `pnpm install`, `pnpm dev`로 실행하고 `pnpm build`로 확인합니다. 애니메이션은 `prefers-reduced-motion` 설정에 따라 꺼집니다.
